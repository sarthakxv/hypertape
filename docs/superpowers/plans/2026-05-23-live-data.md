# Hypertape Live Data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax. Each task: TDD (RED→GREEN), verify, commit (message-only, no body, no Co-Authored-By).

## Context

Hypertape currently serves only fixture data. Even with `HYPERTAPE_DATA_SOURCE=live`, the live provider only fetches `outcomeMeta` and throws on snapshots/tape, falling back to fixtures. This plan makes Hypertape fulfill its USP — a **live probability tape for Hyperliquid HIP-4 outcome markets** — by fetching real orderbooks, mids, candle history, and trades from `https://api.hyperliquid.xyz/info`, and auto-refreshing in the browser.

Branch: `feat/live-data`.

### Verified live API surface (golden fixtures in `test/fixtures/hyperliquid/`)
- `{"type":"outcomeMeta"}` → `{ outcomes: [{ outcome:number, name, description, sideSpecs:[{name}] }], questions: [{ question, name, description, fallbackOutcome, namedOutcomes, settledNamedOutcomes }] }`. NOTE field is `outcome` (not `outcomeId`), `question` (not `questionId`). `description` is pipe-delimited: `class:priceBinary|underlying:BTC|expiry:20260523-0600|targetPrice:77451|period:1d` (priceBucket questions use `priceThresholds:75902,79000`; named outcomes use `index:0`).
- `{"type":"allMids"}` → `{ "#800":"0.043285", "#801":"0.956715", ... }`. One call gives every side's mid. `#800`+`#801`≈1.0 (complementary Yes/No).
- `{"type":"l2Book","coin":"#<enc>"}` → `{ coin, time, levels:[ bids[], asks[] ] }`, each level `{ px:string, sz:string, n:number }`. bids descending, asks ascending. `enc = 10*outcome + side` (coin `#800` = outcome 80 side 0).
- `{"type":"candleSnapshot","req":{coin,interval,startTime,endTime}}` → `[{ t, T, s, i, o, c, h, l, v, n }]` (strings for o/c/h/l/v). `c` (close) = probability mid at candle time → this is the chart history source.
- `{"type":"recentTrades","coin":"#<enc>"}` → `[{ coin, side:"A"|"B", px, sz, time, hash, tid, users }]`.

### Architecture decisions (user + advisor)
1. **Live by default.** `getMarketDataProvider`: live unless `HYPERTAPE_DATA_SOURCE==="fixture"` (dev-only). No automatic prod fallback. Remove `createLiveProviderWithFixtureFallback`, `createFixtureFallbackProvider`, and `HYPERTAPE_FORCE_LIVE_FAILURE`.
2. **Client polling auto-refresh** via API routes seeded with server-rendered initial data.
3. **Full per-market books on the list**, fetched concurrently with a cap of **6**.
4. **No bid=ask=mid hack** for history. Relax `getPrimaryMidFromTwoSidedQuote`: valid if `primaryMid!=null` AND NOT exactly-one-of(bid,ask) is null. i.e. both-present OR both-null (history point) = valid; partial quote = invalid. Candle-derived snapshots have `primaryBestBid=primaryBestAsk=null`, `primaryMid=close`.
5. **Server-side in-memory TTL cache** in the hyperliquid client so M polling clients = 1 upstream call per interval. `allMids`/`l2Book` TTL ≈ 3s; `candleSnapshot` (for 5m/15m deltas + chart) TTL ≈ 20s.
6. **Probability poll = `allMids`** (one call). `l2Book` per market (spread/depth) and `candleSnapshot` per market (deltas) use the longer TTL. 5m/15m deltas return `null` when no candle history (no implicit fallback — the prior 5m fallback bug must not return).
7. **Status derived from expiry**: `expiry < now → "settled"`, else `"active"`, `statusSource:"expiry"`.
8. **Error UX, no fallback**: API routes return `{ source, ...data, error?:string }` with empty arrays on failure; pages render explicit empty/error states; detail `notFound()` when market missing. Never crash the page.
9. **No caching at the edge**: `cache:"no-store"` on every hyperliquid `fetch`; `export const dynamic = "force-dynamic"` on every live API route and live-data page.
10. **One schema**: update dev fixtures to mirror real API shape (`outcome`/`question`, pipe descriptions). One-outcome-per-market model kept; question link is display-only.
